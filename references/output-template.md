# 回覆格式範本

最終回覆一律照這份範本的結構與寫法產出。先看「格式規則」，再看後面的完整範例；範例是「記帳 App，想拉新用戶 D1 留存」的實際回覆，結構、標籤、語氣、長度都以它為準，內容則換成使用者自己的產品與環節。

## 格式規則

### 整體

- 全程繁體中文、全形標點；卡號、英文術語、產品功能名保留原文。
- 不用破折號、不用 emoji、不用粗體強調、不寫奉承式開場或制式結尾。
- 只用三個二級標題，依序是：`## 具體做法`、`## 延伸做法`、`## 其他可行卡`。每條做法用三級標題。
- 具體做法加延伸做法引用的卡不超過 12 張；其他可行卡不受上限，全掃判為可行的全部列出。
- 同一張卡只出現在一個地方：主做法、延伸做法、其他可行卡三者不重複。

### 開頭（一到兩句，放在第一個標題之前）

1. 第一句：使用者要拉的是什麼，以及你用了哪個情境解讀，寫成「我用『產品類型、獲利或取得方式、核心行為』這個情境挑做法」。不要重述使用者的原話。
2. 第二句（使用者沒交代產品現況時才寫）：坦白你沒有對方產品目前流程的資料，已經上線的做法直接跳過。

### 具體做法（5 到 8 條）

每條固定一個標題加四個項目，標籤文字一字不改：

```
### Txxx｜卡片原標題

- 為什麼適合你：……
- 怎麼做：……
- 先這樣試：……
- 看什麼、防什麼：……
```

- 標題：卡號加卡片原標題，不改寫，讓使用者能回查。
- 為什麼適合你：一到兩句。把卡片的「使用時機」翻成使用者產品裡實際會發生的症狀，要具體到一個畫面或一個行為（例如「看完導覽、設完分類，但一筆都沒記」），不寫抽象的「新手不知道價值」。
- 怎麼做：兩到四句，寫成使用者產品裡實際長什麼樣。畫面上的句子、按鈕字、推播文案用「」寫出來；說清楚什麼東西提前出現、什麼東西延後到需要時才出現。素材來自卡片「增補」段的「實際長什麼樣」與步驟裡關鍵的一兩步，不整段複製卡片。
- 先這樣試：一個最小實驗，寫明「改什麼、和什麼比、比哪個數字」。素材來自卡片的「最小可行版本」。
- 看什麼、防什麼：先寫主要指標，用分號隔開，再寫「防的是……」加上處理方式或卡片適用限制裡和使用者有關的那一條。
- 做法之間可以互相指涉（例如「等使用者選完上一條的錨點時段後」），讓幾條讀起來是同一套流程，而不是各自獨立的建議。
- 做法的排列順序依使用者經歷的時間先後（第一次打開、第一個動作、離開後召回），不依重要性。

### 延伸做法

1. 序列一到兩條，每條兩行：
   - 第一行：`序列一：Txxx 短動作 → Txxx 短動作 → Txxx 短動作`。短動作要改寫成使用者產品裡的動作（例如「T331 註冊後先問記帳目的」），不照抄卡片標題。
   - 第二行：一段話說明為什麼這樣接，從使用者的經歷講（例如「這條線就是第一天到第二天的完整回訪迴圈」）。
2. `搭配：` 換行後用項目清單，每項 `Txxx 卡片短名：在使用者產品裡怎麼用，搭在哪一條主做法旁。`
3. `替代：` 換行後用項目清單，每項 `Txxx 卡片短名：什麼情況下改走這條，以及它的成本或限制。`
4. 序列、搭配、替代裡出現、但不在具體做法裡的卡，靠這一句說明就夠，不另開段落。

### 其他可行卡

1. 開頭一句：「這次逐張掃了 A、B 兩個階段共 N 張，再補撈範圍外的卡，可行的有 X 張，上面用了 Y 張，其餘 Z 張如下。」數字照實填。
2. 接一張三欄表格，欄名固定：`卡號與標題`、`用在你的產品`、`為什麼沒放進主做法`。
   - 卡號與標題：`Txxx 卡片原標題`。
   - 用在你的產品：一句，寫成使用者產品裡具體的樣子，可以用「」寫出畫面文字。
   - 為什麼沒放進主做法：一句，只能是這幾類原因：和某張主做法重疊（寫出是哪張）、屬於更前或更後的環節、需要使用者可能沒有的資源或渠道、要先有某個前提。不寫好壞評價，也不暗示排序。
3. 表格列出所有沒出現在具體做法與延伸做法的可行卡，依卡號排序，一張都不省略。
4. 沒有剩下的可行卡時，只寫開頭那句並改成「可行的都已列在上面」，不放表格。

### 結尾（放在最後，不加標題）

1. 固定句：「這些是做法清單，不是優先順序，要排先後可以再用你的資源與限制談。每條都能用卡號回查依據。」
2. 可選一句，接在固定句後面、同一段，以「另外提一句：」開頭：點出一個使用者手上可能就有的數據切法，看了就知道該先押哪一組做法。只能一句，不展開成診斷。

## 完整範例

（以下為完整回覆，實際產出時不要包含這一行。）

---

你要拉的是新用戶隔天回來的比例，我用「個人記帳 App、免費下載、核心行為是記一筆收支」這個情境挑做法。我沒有你們目前新手流程的資料，下面如果有你們已經上線的，直接跳過。

## 具體做法

### T076｜新手只做一個能產生價值的最短任務

- 為什麼適合你：記帳 App 首日流失通常發生在「看完導覽、設完分類，但一筆都沒記」，這張卡處理的就是導覽多、成果零。
- 怎麼做：從資料找出和 D1 關聯最強的首日行為（例如「首日記滿 1 筆」或「首日記 3 筆」），把新手流程砍到只帶使用者做這件事。分類設定、預算、帳戶這些等他第一次需要時才出現。
- 先這樣試：拉留存用戶和流失用戶首日行為的差異，挑最早發生、關聯最強的那一個當門檻；把現有導覽改成「帶你記今天第一筆」一個步驟。
- 看什麼、防什麼：首日完成門檻的比例與完成時間；防的是為了衝完成率讓人亂記一筆測試資料，要回頭看完成者的 D1 和 D7 是否真的比較高。

### T295｜把空狀態改成第一個可做的動作

- 為什麼適合你：記帳 App 第一次打開幾乎一定是空白的帳本、空白的圖表，使用者不知道第一步是什麼就關掉。
- 怎麼做：首頁空帳本不是「目前沒有紀錄」，而是一句「今天花了什麼？」加一顆大按鈕，按下直接進輸入畫面，鍵盤已經跳出、預設分類是最常用的「餐飲」。統計頁的空狀態也改成「記完第一筆就能看到你的花費分布」。
- 先這樣試：只改首頁那一個空狀態，比一週內新用戶從首頁開始記第一筆的比例。
- 看什麼、防什麼：進首頁後完成第一筆的比例；若放示範帳目要清楚標示並可一鍵清除，否則使用者會以為資料不是自己的。

### T117｜把一次小實作接在已有工作或立即享受的活動旁

- 為什麼適合你：記帳最大的問題是「花完錢不會想到要記」，隔天也不會想到打開。這張卡把新行為綁在每天本來就會發生的時刻。
- 怎麼做：記完第一筆後問一題「你通常什麼時候比較有空記帳？」選項是「午餐後」「下班通勤」「睡前」，之後提醒文案寫成「吃完午餐了，記一下這餐花多少？」，而不是「該記帳囉」。
- 先這樣試：讓新用戶自己選一個錨點時段，提醒文案用「做完 X 之後，做 Y」的句型，兩週後關掉一半人的提醒，看還有沒有在同時段記帳。
- 看什麼、防什麼：隔天在選定時段回來記帳的比例；防的是提醒時段選錯變成打擾，要看該時段的推播關閉率。

### T078｜等使用者需要提醒時，先說明權限價值再請求

- 為什麼適合你：D1 幾乎靠推播帶回來，但如果首次開啟就跳系統權限視窗，很多人會按不允許，第二天就沒有任何管道叫他回來。
- 怎麼做：首次開啟不跳權限。等使用者記完第一筆、選完上一條的錨點時段後，先用自己的畫面說「明天晚上 9 點提醒你補記今天的花費，一則就好」，按同意後才呼叫系統權限。
- 先這樣試：把現有的權限請求從啟動時移到記完第一筆之後，前面加一頁自製說明，比系統層允許率和 D1。
- 看什麼、防什麼：推播允許率、收到首則提醒後當天回訪率；拒絕的人不要反覆追問，保留在設定頁自行開啟的路。

### T101｜把延遲成果做成個人進度報告，連到下一次行動

- 為什麼適合你：記帳的價值（看清錢去哪了）要累積好幾天才出現，第一天只記一兩筆感覺不到收穫，這張卡把延遲的成果提早拿出來給人看。
- 怎麼做：隔天的提醒不是「記得記帳」，而是一份極小的報告：「昨天你花了 NT$420，最多在餐飲。今天記完就能看到兩天的對照。」點下去直接進輸入畫面。
- 先這樣試：只對首日有記帳的人，隔天在錨點時段發這則帶數字的推播，和一般提醒文案做對照。
- 看什麼、防什麼：點開推播後完成當日第一筆的比例與 D1；數字只能用使用者自己記的資料，不要誇大成「你省了多少」這種還沒發生的成果。

### T248｜完成有價值的日常練習後，顯示連續完成天數

- 為什麼適合你：記帳本來就是每天做一點的事，符合這張卡「核心任務自然需要頻繁發生」的條件，連續天數能讓第一天就埋下「明天再一筆就兩天」的理由。
- 怎麼做：記完當天第一筆後顯示「已記帳 1 天」，旁邊預告「明天記一筆就連續 2 天」。完成的定義是真的記了一筆收支，不是打開 App。
- 先這樣試：先只做顯示與預告，不做獎勵，三週後比較看得到連續天數的那組 D1 和 D7。
- 看什麼、防什麼：跨日記帳留存；防的是為了保紀錄亂記一筆 1 元，以及斷掉後的挫折感，可以考慮給補記前一天的寬限。

### T105｜把工具入口放進使用者本來會做的工作

- 為什麼適合你：花錢的當下在收銀台、在別的 App 裡，不會專程打開記帳 App，入口越靠近付款那一刻，隔天越容易繼續。
- 怎麼做：在付款發生的場景放能直接記一筆的入口，例如桌面小工具、iOS 捷徑或 Siri、Android 通知列快速記帳。記完不用進 App 首頁。
- 先這樣試：訪談十位新用戶，問他們花錢後通常在做什麼、手機停在哪個畫面，挑最多人提的一個做最小版本的快捷入口。
- 看什麼、防什麼：透過快捷入口完成的記帳佔比，與有用快捷入口者的 D1；防的是入口壞掉或資料漏存，要有失效時的替代路徑。

## 延伸做法

序列一：T331 註冊後先問記帳目的 → T076 只帶記第一筆 → T295 空狀態變成第一個動作
想控制花費、想存一筆錢、和另一半分帳，這三種人的第一筆長得不一樣。先用一題分流，T076 和 T295 給的範例和預設分類才會貼到本人。

序列二：T117 選錨點時段 → T078 在那個時刻請推播權限 → T101 隔天送帶數字的小報告 → T248 顯示連續天數
這條線就是第一天到第二天的完整回訪迴圈：先決定什麼時候叫他，再拿到叫他的權限，用他自己的資料叫他回來，回來後給他明天再來的理由。

搭配：
- T119 讓使用者稍後決定：首次開啟沒空記的人，給一個「今晚提醒我補記」按鈕，只提醒一次，搭在 T078 旁邊。
- T075 匯入已累積資料：如果能匯入雲端發票或銀行交易，第一天就有十幾筆真實資料，搭配 T295 讓空帳本一打開就不空。

替代：
- T336 把累積資料可視化：不想靠推播時的另一條路，但新用戶數字太小可能反效果，比較適合用在 D7 之後。
- T312 辦 7 天記帳挑戰：有社群或電子報名單的話，用公開打卡取代 T248 的個人連續天數，經營人力成本較高。

## 其他可行卡

這次逐張掃了 Activation、Retention 兩個階段共 147 張，再補撈範圍外的卡，可行的有 23 張，上面用了 12 張，其餘 11 張如下。

| 卡號與標題 | 用在你的產品 | 為什麼沒放進主做法 |
|---|---|---|
| T064 把模糊按鈕改成動作加結果，集中一個主要行動 | 首頁主按鈕從「新增」改成「記一筆今天的花費」，其他入口降成次要 | 和 T295 重疊，可以在改空狀態時一起做 |
| T066 刪除首次任務前不必要的欄位與幹擾 | 第一筆只要金額和分類，帳戶、備註、照片等第二筆以後再出現 | 和 T076 重疊，是砍新手流程時的具體檢查清單 |
| T071 先讓人操作核心功能，需保存時纔要求註冊 | 不註冊也能先記帳，等使用者要開雲端備份或換機時才請他建帳號 | 前提是你們目前有強制註冊，沒有的話不適用 |
| T077 在陌生操作發生處給提示，熟手保留快捷方式 | 第一次出現左滑刪除、長按複製帳目時才跳一次小提示 | 屬於第一筆之後的操作細節，對 D1 影響較間接 |
| T079 按啟動中斷點發下一步訊息，完成後即停止 | 「下載沒記帳」「記了一筆沒開提醒」各送一則不同的推播，做完就不再收 | 需要已有推播權限，要先做 T078 |
| T104 跨渠道共用提醒狀態，控制總頻率並排除已完成者 | 推播、Email、LINE 共用同一個「今天已記帳」狀態，記過就全部停發 | 需要你們同時有兩個以上的通知渠道 |
| T128 讓共同編輯、分攤或規劃直接帶出邀請 | 記到「和朋友聚餐」這類帳時，直接帶出「邀他一起分帳」 | 主要拉推薦與共用帳本，對新用戶隔天回訪是間接效果 |
| T259 讓完成核心任務的人立即看見進展並得到相符獎勵 | 記完第一筆立刻顯示「今天已記 1 筆，這週已掌握 1/7 天」 | 和 T248 重疊，二擇一即可 |
| T264 在確有登入需求處提供熟悉帳號的登入選項 | 需要註冊時提供 Apple、Google、LINE 登入，不另設密碼 | 屬於註冊環節，前提是首日有註冊步驟 |
| T294 用新手任務清單與進度條帶到首次價值 | 首頁放三項清單：記第一筆、設定提醒時間、看一次本週圖表 | 和 T076 方向相反（一個步驟對多個步驟），二擇一 |
| T314 LINE 官方帳號加好友送首購優惠，之後用標籤分眾推播 | 首日引導加 LINE 好友，隔天用 LINE 送記帳提醒，作為推播被拒時的備用渠道 | 需要經營 LINE 官方帳號，且「首購優惠」要換成記帳 App 適用的誘因 |

這些是做法清單，不是優先順序，要排先後可以再用你的資源與限制談。每條都能用卡號回查依據。另外提一句：D1 很大一部分在首日就決定了，如果手上有「首日有記帳 vs. 沒記帳」兩群的 D1 差距，那個數字會告訴你該先押首日記第一筆，還是隔天的召回。
