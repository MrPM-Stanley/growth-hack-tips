# 更新卡片 SOP

使用者給一個或多個套路卡 MD 檔，要新增或更新到這支 skill 時，照這份流程做。程式都在 `scripts/ght_admin.py`，純 Python 3，不需安裝套件。

## 0. 準備

1. 已安裝的 skill 資料夾是唯讀的。把整個 skill 資料夾複製到工作資料夾，資料夾名稱維持 `growth-hack-tips`，以下指令全部在複本裡跑。
2. 先跑 `python3 scripts/ght_admin.py validate`，確認起點是 0 錯誤。不是 0 就先告訴使用者，不要疊上新改動。
3. 一個檔一張卡。一個檔裡有多張卡時，先拆成多個檔。MD 上標的卡號一律忽略，卡號由程式自動接最大號。

## 1. 判斷重疊

四個步驟都要做，不能只看第一步的排名：

1. `python3 scripts/ght_admin.py overlap 卡片.md`：依標題、使用時機、步驟的相似度列出候選。分數只用來排順序。
2. `python3 scripts/ght.py scan --stage <新卡的階段>`：逐張讀同階段每張卡的標題和使用時機，找做的是同一件事的卡。
3. 用新卡核心做法的兩種不同說法，各跑一次 `python3 scripts/ght.py search "<說法>" -n 10`。
4. 用 `python3 scripts/ght.py show <卡號...>` 讀候選卡全文，逐張和新卡對照。

判斷標準：

| 判斷 | 條件 | 怎麼處理 |
| --- | --- | --- |
| 完全重疊 | 使用時機一樣，核心步驟也一樣；新卡只是換說法、換產業或換例子 | 不新增。新卡有既有卡沒有的例子、限制或來源，就併進那張既有卡（見第 3 步的覆寫）；什麼都沒多，就跳過並告訴使用者是哪張 |
| 部分重疊 | 新卡有一部分做法既有卡已經有，但另有既有卡沒有的使用時機或關鍵步驟 | 新增成新卡。標題和使用時機要寫出新的那部分，並和重疊的既有卡設相關套路。如果新的東西只是一個案例，撐不起一張卡，就改成併進既有卡的增補段 |
| 不重疊 | 找不到做同一件事的卡 | 直接新增 |

相關套路怎麼設：同時做會互相加強的是「搭配」，解同一個問題的另一條路是「替代」，有先後順序的是「前置」與「後續」。至少一條，只寫卡號。

## 2. 整理成資料集格式

只改格式和段落位置，不改原意；改了哪些地方，回報時要列給使用者。

```
# 卡片標題（一句話寫出做法）

AARRR：Revenue（變現）

主題：定價、方案與商品組合、付費轉換優化

## 使用時機
## 適用情境
## 具體步驟
## 如何衡量
## 為何歸在這些階段
## 適用限制
## 增補：具體做法範例
## 相關套路
## 來源
```

各段規則：

- 標題：不寫卡號，程式會補。
- AARRR：用 Acquisition、Activation、Retention、Referral、Revenue 這五個；寫成中文（獲客、營收等）也認得。
- 主題：只能用 `ght.py topics` 列出的既有主題，寫 id、中文名或別名都可以。MD 寫的主題不在裡面時，先提出最接近的既有主題，請使用者確認；使用者不在場就用最接近的，並在回報裡說明換成了什麼。不自行新增主題；使用者明確要新增，才去改 `data/taxonomy.json`。
- 使用時機、適用情境：各寫一行。適用情境寫產業或商業型態，用分號隔開；「不能……」這類條件句移到適用限制。
- 具體步驟：編號清單，每一步都是做得出來的動作。讀起來是心法（只有確認、整理、檢查）就退回給使用者。
- 如何衡量：至少有「主要指標」和「防止副作用的指標」兩行，可以另加過程指標。
- 為何歸在這些階段：每個階段一行，格式「- Revenue：理由」。不提會議、文件這類來源脈絡。
- 適用限制：項目清單。
- 增補：一定要有「實際長什麼樣」和「最小可行版本」。「公開案例」有才寫，沒有就整行省略，不寫「未另引」。
- 相關套路：「- 搭配：T145」這種格式，一行一條。
- 來源：項目清單。說明性質的行用「註：」開頭，例如「註：以上來源與本卡機制為部分對應」。
- 不收：證據性質段落、會議分析筆記、數據口徑的討論（必要時濃縮成一句放進例子裡）。

內部資料：來源是內部會議、私人雲端連結（Google Drive、Dropbox 分享連結等），或卡片裡有未公開的公司數字時，先問使用者要照留、只拿掉人名與連結，還是只留做法。這支 skill 可能公開發佈。使用者不在場時，預設拿掉人名、公司名、金額與私人連結，數字改寫成比例，來源寫「內部××紀錄（未公開），日期」。程式不會把私人網址放進 `source_urls`。

## 3. 寫入

1. 預覽：`python3 scripts/ght_admin.py add 卡片.md --dry-run`。格式不對會列出要修的地方，修好再跑。
2. 新增：`python3 scripts/ght_admin.py add 卡片.md`
3. 併進既有卡：拿既有卡全文（`ght.py show Txxx`），把要併的內容寫進去，存成 MD 後跑 `python3 scripts/ght_admin.py add 合併後.md --replace Txxx`。卡號、檔案位置、`added` 都會保留。
4. 刪卡：只在使用者明確要求時才跑 `python3 scripts/ght_admin.py remove Txxx`。

程式會自動處理這些：相關套路的雙向連結（替對方卡補上或移除反向連結）、`content_sha256`、`taxonomy.json` 的 `tactic_count`、SKILL.md 描述與 `data/README.md` 裡的總張數；資料檔超過大小上限時會開新的 `tactics-N.jsonl`。

## 4. 收尾

1. `python3 scripts/ght_admin.py validate` 必須是 0 錯誤。
2. 在 `data/README.md` 的「變更紀錄」最上面加一筆：日期、新增或修改的卡號、重疊判斷、被牽動相關套路的卡號。
3. 如果開了新的 `tactics-N.jsonl`，把 SKILL.md 和 `data/README.md` 裡寫的檔案範圍（例如「tactics-1.jsonl 到 tactics-7.jsonl」「七個檔」）一併改掉。
4. 用 `python3 scripts/ght.py show <新卡號>` 和 `python3 scripts/ght.py expand <新卡號>` 確認新卡查得到、連結展得開。
5. 打包成 .skill：刪掉 `__pycache__` 與 `.pyc`，壓縮檔根目錄放 `growth-hack-tips/` 資料夾本身（SKILL.md 在資料夾裡），副檔名改成 `.skill`，交付前列出壓縮檔清單檢查層級。請使用者重新安裝。

## 5. 回報

每張卡一行：卡號｜標題｜重疊判斷（不重疊／部分重疊，和哪幾張、重疊在哪／完全重疊，併入哪張）｜改寫了哪些地方。最後附 .skill 檔路徑，並提醒使用者重新安裝。
